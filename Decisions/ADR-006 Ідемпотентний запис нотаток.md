# ADR-006 Ідемпотентний запис нотаток

## Контекст
Повторний виклик ingest_note не повинен створювати дублікати чи порожні коміти; невдалий push не повинен лишати vault розсинхронізованим (коміти b98411d, e665157, ПР3).

## Рішення
Нотатка ідентифікується назвою. Сервер порівнює новий вміст із наявним і повертає status=unchanged, якщо різниці немає; при цьому він допушує коміти, що не потрапили на віддалений репозиторій. Нова нотатка автоматично додається в розділ MOC. Дата створення зберігається при оновленні.

## Альтернативи
Хеш у frontmatter (зайве ускладнення).

## Наслідки
Історія git лишається малою, повторні виклики безпечні, vault зв'язний.
