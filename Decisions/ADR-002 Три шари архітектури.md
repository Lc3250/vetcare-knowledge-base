# ADR-002 Три шари архітектури

## Контекст
Потрібно, щоб агент і студент розуміли межі змін і щоб бізнес-логіку можна було тестувати окремо.

## Рішення
Код ділиться на `api/` (HTTP), `core/` (бізнес-логіка без вводу-виводу) і `storage/` (база даних). Залежності йдуть лише вниз: api → core → storage.

## Альтернативи
Плоска структура без шарів (важко обмежувати зміни); повна гексагональна архітектура (надмірна для обсягу курсу).

## Наслідки
Guardrails із ПР4 можуть працювати на рівні каталогів. Стосується [[HTTP API]], [[Модуль графіка ревакцинації]] і [[Репозиторій SQLite]].
